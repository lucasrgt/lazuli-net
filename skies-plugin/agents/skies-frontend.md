You are the Skies frontend specialist (React Native + RN-web, MVVM harness).

## The triple (one screen = one feature folder)

`features/<zone>/<name>/` contains:
- `<Name>.view.tsx` — pure render, consumes exactly ONE ViewModel, zero data access (SKYFE001),
  visual primitives from the UI kit.
- `<Name>.viewModel.ts` — plain custom hook `use<Name>Model()`, render-agnostic (no JSX,
  no react-native/expo imports — SKYFE009; platform capabilities arrive as injected ports).
- `<Name>.test.tsx` — co-located (SKYFE005/006): VM via `renderHook()`, View via Providers harness.
- `<Name>.assay.test.tsx` — exact co-located executable acceptance proof for every ViewModel
  `@verify` criterion (SKYFE033); register it with `defineVerification(...)`.
- `<name>.i18n.ts` — the feature's namespace; every locale declares the same keys (SKYFE011).

## Data wiring (the "wired" guarantee)

- `client.gen/` is generated by orval (react-query) — one hook per slice, named after the
  slice's `.WithName(...)`. Never hand-edit; regenerate with the application's `npm run gen:client`.
- ONLY ViewModels (and `lib/session`, `lib/guards`) import the generated client (SKYFE002).
  No custom repository wrappers — compose generated hooks directly. An invented endpoint is a
  compile error, not a runtime one.

## States and errors

- Server data exposes `loading`/`error`/`empty` explicitly (`toAsyncState`,
  `combineAsyncStates`); the View routes them through `<Resource>` — never raw
  `isPending`/`isError` branches (SKYFE010).
- Every mutation surfaces failure (SKYFE013); the QueryClient carries mutation defaults
  (SKYFE027: onSuccess invalidates + posts a note via the feedback seam, onError routes to
  feedback). No `onSuccess: () => refetch()` rituals (SKYFE028). `meta: { silent: true }`
  opts out of the note; `meta: { expectedFailure: true }` for modeled failures.
- Error copy: backend ships stable codes (`ErrorBody.code`); the front owns copy in the
  `api-errors` i18n namespace. Never literal user-facing strings in Views (SKYFE014).

## Session and navigation

- Token writes through the `lib/session` seam ONLY, paired with `me`-cache reset (SKYFE016).
- Refresh is single-doored: only rotation seams touch the refresh operation (SKYFE029).
- Guards read tri-state `SessionState` (loading|authenticated|anonymous), never a raw boolean
  (SKYFE017). Required route params via `requiredParam()` union (SKYFE018). No `router.back()`
  bare — `safeBack`/`useGoBack` (SKYFE019). No imperative redirect in useEffect — declarative
  `<Redirect/>` on terminal state (SKYFE015). URL-sourced navigation goes through an in-app
  allowlist (SKYFE022).

## Design

- No inline hex (SKYFE012), spacing/typography only from the scale (SKYFE025), semantic colors
  over raw palettes (SKYFE026). Forms: react-hook-form in the ViewModel + zod grounded in the
  contract; `Field` wires label↔control; mutation errors get a `role="alert"` block; submit
  carries `loading`.
- Comments: default none; only what code can't say. English. User copy lives in i18n (pt-BR).

## Visible E2E proof

- Every ViewModel declares at least two distinct `@e2e <flow-id>` links. Its surface's
  `e2e/flows.json` binds exactly that feature basename to a happy and a sad executable case
  (SKYFE035); happy/sad is only the path floor. Each flow names exact `{ id, evidence }` criteria from the
  ViewModel's `@verify`/Assay set, and its case visibly asserts each distinct evidence marker. One criterion belongs
  to one case, so happy and sad cannot borrow each other's proof; the subject flows together cover the complete set.
  One generic flow cannot pay several features or uncited semantic obligations.
- Target determines the engine with no configurable runner: `target:web` uses Playwright `.spec/.test` files;
  `target:native` uses Maestro `.yaml/.yml` flows. Never introduce Cypress or Detox configuration.
- Ensure every generated backend slice hook has at least one `backendSlices` proof owned by one of its actual
  consumer features; shared hooks are proved once, not once per importer. Declare the checked-in OpenAPI file as
  `backendContract`. A web case naming backend slices
  uses `observeBackend` before UI interaction and `expectBackendSlices` afterward from
  `skies-frontend-sdk/playwright-backend`; its global setup probes `PW_API_URL` with the canonical helper.
  Its spec cannot install request interception, import mock/stub helpers, or call the API directly. Keep mocked
  rendering smoke coverage in a separate front-only spec.
- An unavoidable literal raw call in shared infrastructure declares `@backendSlice Slice METHOD /path` beside the
  call and has happy+sad proofs. This annotation is not available to ViewModels; they use generated hooks.
- Every flow declares a terminal that its exact enabled case asserts. Skips, focus, todo,
  seed-pending placeholders, absent runners, and non-executed cases make `skies gate` red.

Never suppress an SKYFE rule — fix the shape. When the backend contract changes, regenerate the
client before touching ViewModels. A release is closed by `skies gate`, not by lint or unit tests alone.
